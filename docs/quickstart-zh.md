# MIXED-API 使用指引

先按 [逐步配置指引](quickstart-guided.md) 操作。以下说明用于内置核心开发分支：EXE 启动自己的工作台窗口。

## Key 不要混用

- **客户端 Key**：工作台复制，填到 Cherry Studio、SillyTavern 等 AI 客户端。
- **Admin Key**：只用于本机后台管理；EXE 启动会自动连接，手动访问可从私密的 mixed-api.json 查找。
- **快速V Express Key / OpenCode Zen Key**：来自各自官方账号，只填到相应来源第 2 步。不是 MIXED 的客户端 Key。
- **已有 HTTP 服务 Key**：仅在手动服务配置中填写，用于连接你自己的外部服务。

## Android → 电脑

1. 电脑打开「局域网模式」快捷方式（或 EXE 参数 `--lan`），接好所需来源。
2. 在电脑用 `ipconfig` 查看实际局域网 IPv4。手机电脑连同一可信 Wi-Fi。
3. 手机点击「电脑 MIXED-API」，按步骤填写 `http://实际电脑IP:8766/v1` 和电脑客户端 Key；这是手机网关连接电脑的内部设置。
4. 手机 AI 客户端填 `http://127.0.0.1:8765/v1` 和手机自己的客户端 Key；模型从手机模型页复制，电脑来源前缀为 `pc/`。

电脑掉线或关闭后，对应模型也会不可用。局域网端口不提供后台管理，不要映射到公网。

## 常见问题

- **快速V没有 Express Key**：在第 2 步点击申请入口，按 Google 官方要求获取；MIXED 无法代替你创建账号权限。
- **安装完成却没有模型**：安装、授权、模型目录和实际推理是不同的事情。按第 2、3 步检查，不会自动改用别的来源。
- **无头V授权未就绪**：在官方来源窗口完成本人确认，并发送一条测试消息，再返回配置。窗口失效时重新打开；服务方的地区、账号或额度限制仍然适用。
- **Key/地址填错**：在配置窗口点「返回上一步」进入已有服务高级设置；普通自动接入不需要改内部端口。
- **模型检查曾成功、现在失败**：本次读取失败不会使用上次目录冒充验证通过；排除网络/授权问题后重新检查。
- **关闭窗口**：关闭 Windows 主窗口会退出网关并清理来源窗口；单独关闭来源窗口只隐藏该窗口，供已授权请求继续使用。Android 返回来源窗口会回到工作台，后台服务由应用控制。

## 签名、升级与备份

Windows 安装包会保留配置；脚本升级还会在安装目录备份 `mixed-api.json`。原生令牌在配置旁 `.mixed-accounts`，Windows 官方会话在 `%LOCALAPPDATA%\MIXED-API\provider-*`，备份时一并保管。不要把配置备份或会话文件提交到仓库。

Android 开发分支使用不可调试的 Release 构建。正式包必须沿用固定签名，CI 会核验证书指纹，并在模拟器中测试覆盖安装后配置和加密账号仍可读取。PR 产物仅用临时测试签名，不能作为稳定升级渠道；维护者配置见[Android 签名](android-signing.md)。

旧 v0.3.1 使用随机 Debug 签名，和新固定签名不一致时 Android 会拒绝覆盖安装。不要先卸载旧包：卸载会删除本地配置、账号和 Keystore 密钥；先自行保存连接配置和来源设置，切换后重新完成本人授权。不能通过复制加密账号文件跨卸载恢复账号。新签名之间的升级测试不代表旧版数据迁移已经验收。

实际个人账号推理、Android 真机安装及保活未全面验证；请以真实设备和账号的测试结果为准。
