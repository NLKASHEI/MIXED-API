# v0.3：接入、诊断与可重复发布

目标：用户安装后能清楚地选择来源、完成本人授权、验证模型，再复制地址、Key 与模型 ID 到客户端。

1. 核对六个 GitHub 原仓库，记录核对日期、默认分支、HEAD、最新正式版和发布资产哈希。正式安装只使用经过审查的固定版本，不自动追踪未发布 HEAD。
2. 重建共享网页控制台：浅色、简约排版，来源接入、三步向导、可搜索模型、诊断、设置和更新。Windows EXE 默认打开新版控制台并自动连接本机，无需输入 Admin Key；旧原生窗口移除。手机使用同一份响应式 HTML。
3. 并发发现各来源模型，一个慢来源不阻塞其他来源的探测。模型按配置顺序稳定输出、去重；空列表和无效响应不能报成功。管理诊断提供来源状态、耗时、错误和下一步，结果不包含配置密钥。
4. 密钥权限及 LAN 隔离不变；拒绝向重定向目标发送上游凭证；不记录提示词。Codex 保留本人登录与工具隔离，安装固定正式版，验证实际 CLI 参数。
5. 提供 Windows 一键下载脚本，验证官方 Release SHA-256、保留配置、部署到明确目录；为无 Go 环境用户提供可用的安装包。备份与升级说明明确。
6. CI 验证共享页面一致性、JS、Go 测试/race/vet、Windows 安装包和 Android Gradle/lint；版本号在所有资产中一致，发布 SHA256SUMS 和包含实际变更的 Release 说明。

测试接口已由 AGENTS.md 规则 1、5、6 确定：公开 HTTP 路由、共享静态页面、Windows 编译与 Android CI。测试不使用个人账号，不执行上游登录或付费推理；真实账号推理与 Android 真机行为必须明确列为未验证。

工程方法：使用 mattpocock/skills 的 tdd、codebase-design、code-review。基准为接手时的 dd719fb；实现后按规范与本规格分别审查。

用户追加：界面正文整体放大，新增独立 `/admin` 后台。客户端始终只填写一个统一 URL；内部传输地址仅在主动展开的已有服务设置中显示。`vertex` 对用户命名为“快速V”，第 2 步必填 Express API Key；`aps` 命名为“无头V”。本地包和 APS 属同一谱系，由程序内部整合，不新增 `vertex_local` 来源、不提供组件版本选择。

本地包构建元数据来自旧 `bsfdsagfadg/vertex`（已重定向 APS2api），含 dirty 标记且公开仓库找不到该提交，不能冒充官方可复现构建。维护导入保留原目录，在隔离目录配置组件，自动用于无头V；不复制账号数据库或规则同意状态。后台直接解释超时、重试、回复显示方式的作用，不使用“增强引擎参数”等不明术语。

每个来源都须有实际分步引导：①只准备组件；②按该来源给出授权入口、获取信息的方法与当前输入，用户确认后激活；③明确检查模型，再提供唯一客户端地址、客户端 Key、模型 ID。不能把全部按钮和所有说明一次堆给用户，不能自动跳过授权确认。
