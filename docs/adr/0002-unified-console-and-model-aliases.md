# ADR-0002：统一交互、组件生命周期与模型别名

状态：Accepted，2026-10-16。补充 ADR-0001 的公共路由规则，取代旧 Win32 界面选择。

统一应用层由 MIXED 实现：分步接入、单一客户端入口、模型目录、明确目标的别名、诊断、后台管理与可重复发布。依赖不同运行时的协议引擎作为内部受管组件，首次账号授权仍由本人完成；不把多套服务的地址暴露为多套客户端连接。

同一功能的组件实现不作为新的来源或用户版本选择。提供的本地 Vertex Proxy 包构建路径为旧 bsfdsagfadg/vertex（已重定向 APS2api），因此合入既有 aps 来源；维护导入后该组件优先，原数据保留在原目录。它的 modified 构建不能冒充可复现官方发布，也不随网关 Release 重新分发。普通用户只看“无头V”；vertex2openai 的 Express 接入对用户称“快速V”。

准备步骤只能安装/生成配置，不能提前启用来源；用户确认授权之后才激活。无头V首次规则确认，无论使用哪个内部组件，都须提供真实交互窗口，不伪造同意记录。快速V激活时重启已运行的受管进程，确保新 Express Key 生效。

默认公开模型仍采用 backend/original 命名。新增的可选别名是例外：简单名称明确绑定到一个已配置的 backend/model；不允许链式别名，不自动选择另一供应商。仅在目标模型当前可枚举时，将该别名加入目录。可枚举不等于已获推理权限。Android pc 桥接保留电脑原始模型 ID，其本地别名用 pc/目标ID 明确绑定桥接。

管理页 /admin 和 /api/* 只通过回环管理监听提供，客户端 Key 不授权；LAN 监听继续只提供 /v1/* 与 health。无头V组件自身可能监听所有网卡，不把网关的回环绑定误称为组件网络隔离。

新界面、HTTP 行为与 Android 页面保持一致。Windows 部署和 Android 构建分别验证；浏览器测试、模拟上游和 CI 不替代个人账号推理及真机测试。
