# 后续规格：一体化桌面应用

状态：2026-10-17 确认的要求，**尚未完成全部验收**。用户随后明确要求先发布电脑版，再补 APK；v0.4.0 按已验证范围发布 Windows 内置核心版与 Android 测试版，保留真实账号、干净 Windows 和实体设备等未验收事项，不表示本规格全部完成。具体进度见[内置重构进度](integration-progress.md)。架构依据：[ADR-0003](adr/0003-integrated-desktop-core.md)。

跟踪：[GitHub Issue #3](https://github.com/NLKASHEI/MIXED-API/issues/3)。

## 用户最终拿到什么

一个安装包或完整便携包。双击 EXE 后出现 MIXED 自己的应用窗口，保留简约、大字号界面、后台和配置每一步的指引。用户无需先安装 Go、Node、Python、上游代理程序或额外浏览器运行资源。

用户只处理自己的账号授权、必要的 Key 和实际使用选项；六路共用一个客户端连接地址。快速V明确要求 Express API Key，无头V不出现内部版本选择。参数在当前配置步骤解释用途。

## 核心融合要求

协议转换、请求组织、流式响应、错误处理、取消与反代算法融入应用模块，共享基础能力。只把上游 EXE 放入资源或把下载过程隐藏，不满足这一条。账户数据不进入安装包。

实现前为每个来源维护能力清单：可核验上游提交、代码来源与许可、拟纳入的核心能力、对应测试、剩余外部依赖。用户本地无头V包作为同源能力核对输入，不单列来源，也不把不可核验的 modified 二进制视作源码。

| 来源 | 必须核对的集成边界 |
| --- | --- |
| 快速V | Express Key 请求、模型与协议转换、流式响应和错误语义 |
| 无头V | 官方 APS 与本地同源包的功能差异，实际采用的反代、重试、超时和模型能力 |
| Codex | 授权、会话与请求适配；现有调用外部 CLI 的方式必须替换或明确列为未完成 |
| OpenCode | 实际上游请求、认证及协议能力，取消下载独立代理程序 |
| WorkBuddy | 官方客户端依赖能否被合法且完整的应用模块替代，未解决不能宣称独立运行 |
| AI Studio | 浏览器授权与请求所需资源的随包交付，以及代理逻辑内置 |

## 验收条件

1. 干净 Windows 虚拟机中未安装 Go/Node/Python/上游、无既有组件缓存。安装与便携两种交付分别验证；断网可以启动独立窗口、打开后台、加载本地核心和所需运行资源。断网验收不要求云端模型推理成功。
2. 启动 EXE 不调用默认浏览器打开本机控制台。授权时按服务要求打开浏览器可以接受；不能把浏览器标签页或旧 Win32 表单当成新的主窗口。
3. 正常启动和来源配置不调用 winget/npm/pip、不获取上游源码或 Release、不临时下载浏览器/渲染器。记录文件、进程和网络行为，不能只靠源码关键词检查。
4. 六路逐项用公开 HTTP 接口编写先失败后通过的行为测试，覆盖模型命名冲突、认证、流式响应、取消、错误和禁止跨来源回退。模拟测试与个人账号实际推理分别记录；不以可枚举模型替代推理证据。
5. 独立窗口实际验证字体、后台、三步引导、复制唯一 URL、退出与进程生命周期；若沿用共享 HTML，保持 Android 页面与配置一致并记录平台差异。
6. 更新与便携迁移保留配置，打包依赖来源与版本可追溯；不把用户数据或授权状态打入发布资产。
7. 逐项对照本规格和工程标准进行双轴审查。Go test/vet、适用的 UI 检查和 Android Gradle CI 通过；发布资产必须来自实际成功的 Actions 构建。另行记录干净 Windows 的真实产物验证，不以 CI 代替。

## 完成定义

以上每项均有实际证据，才能把相应功能标成已内置。若仍有依赖用户安装上游或官方客户端的来源，明确列为未完成；不得将整个版本宣传成“所有核心已内置、无需额外安装”。本要求记录本身不触发新的功能 Release。
