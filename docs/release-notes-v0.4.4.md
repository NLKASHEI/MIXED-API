# MIXED-API v0.4.4 — 修复登录页面关闭与无头V等待

- 修复 AIS 登录、验证期间浏览器连接短暂中断就自动关闭官方标签页的问题。未执行生成时保留页面，在原标签页最多尝试3次重连，不重新跳转或打断本人登录。
- 修复无头V把普通帮助面板等非模态 dialog 当成待处理授权的问题，排除隐藏窗口。真正的模态条款、登录与验证仍由本人操作。
- 无头V匿名验证不再要求找到聊天输入框或清空草稿；连接过程不向聊天输入框填字、不发送测试生成。
- 等待状态区分官方页面加载、登录跳转、连接中断、reCAPTCHA脚本加载和实际阻塞窗口，不再把脚本或通信故障一律说成用户尚未授权。
- 重连不重放生成。连接中断时拦截迟到的初始化/生成命令；真正存在且无法确认取消的生成仍终止其受控标签页，避免旧请求继续运行。

## 更新

完全退出旧版后使用新版 EXE，保留 mixed-api.json。在AIS/无头V步骤打开官方页面，让新版释放连接组件；到 `edge://extensions`（Chrome为 `chrome://extensions`）刷新“MIXED 浏览器连接”，然后回软件重新点击“打开官方页面”。旧扩展的后台脚本不会因为替换EXE自动更新，这一步需要做一次。之后本人完成官方页面操作，软件自动等待并连接。

使用浏览器自己的代理设置。若提示reCAPTCHA脚本尚未加载，先检查浏览器访问Google及reCAPTCHA的网络；若显示具体模态窗口，按官方页面处理。界面不会替本人确认条款、登录或挑战。

发布资产由本标签成功的GitHub Actions构建，Android继续暂停，本版不附APK。此次核心回归覆盖登录页保留、原标签重连、迟到请求阻断和无头V模态识别；不把模拟验证函数成功当成本人Google账号真实生成已通过。真实账号问题继续跟踪 [Issue #5](https://github.com/NLKASHEI/MIXED-API/issues/5)。
